# 第一阶段：上传录音到笔记

日期：2026-11-13。范围：上传录音（可带 PDF 课件）到笔记显示在课堂页，这一条路走通。

## 为什么做、做到什么程度

前端（`src/`）一直跑在示例数据上（`USE_MOCK: true`）。这一阶段做最小的闭环：学生上传一段课堂录音，后端转写、写笔记，前端把 `USE_MOCK` 改成 `false` 就能在课堂页看到。同时把每堂课的成本记下来，回答 `reference/INTEGRATION.md` 第 10 节的定价问题。

**做到**

- 11 个接口：`POST /session`、`GET /home`、`POST /courses`、`POST /lectures`、`POST /lectures/:id/recording`、`POST /lectures/:id/slides`、`POST /lectures/:id/finish`、`GET /lectures/:id/status`、`POST /lectures/:id/retry`、`GET /lectures/:id`、`DELETE /lectures/:id`。
- 处理流程：存文件 → 转码 → 转写 → DeepSeek 写笔记 → 校验 → `ready` 或 `failed`。
- 每堂课的成本日志（音频分钟、token、估算美元），以及汇总脚本。
- 两家转写服务，加一个用真实录音对比它们的脚本。
- 契约测试（回复的形状对得上 `src/types.ts`），以及转写服务和写笔记模型都换成假实现的流程测试。

**不做（后面的阶段）**

- 现场录音的分段上传、Catch me up、录音回放（本阶段 `detail` 不带 `audio`，前端不显示播放器）。第二阶段已做。
- 编辑笔记、分享、学习进度、复习包、课程管理、搜索、课后补传课件。
- 会员方案、付款、正式登录。

**算失败的情况**：接口形状和前端对不上；上传中断后留下残缺文件；同一堂课被重复扣费（重试重新转写、`finish` 被调用两次各跑一遍）；模型写出的东西不合规矩却被标成 `ready`。

## 考虑过的做法

**写笔记：一次调用 vs. 分段调用。** 一堂 90 分钟的课转写下来约 2 到 3 万 token，DeepSeek V4 的上下文是 100 万，一次调用就能装下整堂课和课件。分段调用（先分主题，再逐段写要点）能并行，但要多一轮协调，主题边界也容易对不齐。选一次调用；以后真的超时或质量下降再拆。

**课件：直接给模型 PDF vs. 先抽文字。** DeepSeek 的接口对 PDF 的支持没有明确文档。所以先用 `pdfjs-dist` 逐页抽出文字，按“Slide n: 文字”给模型，用来判断要点属于哪一页、`off`（课件上没有）是否成立。缩略图本阶段不做（`slide.image: null`，前端显示页码和标题）。

**逐字稿：让模型输出 vs. 直接用转写结果。** 让模型把逐字稿再写一遍，既贵又可能改字。所以 `detail.transcript` 直接由转写的词和时间戳切成句子；模型只写要点、分节、提示、闪卡和测验。

**大文件上传：Hono 的 `parseBody` vs. 流式解析。** `parseBody` 会把整个文件读进内存，500 MB 的文件不行。所以用 `busboy` 边收边写临时文件，收完整了再改名放到位；请求中断就删掉临时文件。`Content-Length` 超过上限的请求直接回 413，不读请求体。

## 接口行为

通用：

- 所有路径在 `/api` 下（前端 `API_BASE: "/api"`）。出错一律回 `{ "message": "..." }`，这句话会直接显示给用户。
- JSON 请求体最大 64 KB，超过回 413（包括不用登录的 `POST /session`）。上传文件的请求最长可以持续 3 小时（Node 默认 5 分钟，慢网速传 500 MB 会被切断）。
- 分享页的 `GET /shared/:id` 不用登录，本阶段一律回 404 和说明（不能回 401，否则前端会让读者“重新登录”）。
- 除 `POST /session` 外都要 `Authorization: Bearer <token>`，token 无效或缺失回 401。
- 别的用户的课程和课堂一律当作不存在，回 404。
- 文件超过 `MAX_UPLOAD_MB`（默认 500，和前端一致）回 413。

| 接口 | 行为 |
|---|---|
| `POST /session` `{inviteCode, name}` | 码不对回 401 加说明（前端对这个公开接口原样显示）。给了 `name` 就更新名字。回 `{token, user}` |
| `GET /home` | `user`、`courses`、`lectures`（新的在前）、`upcoming`（从笔记里带日期的考试和截止提示汇总，只给今天及以后的）、`settings`、`usage`、`today`（按 `APP_TIMEZONE`，默认香港）。`week` 本阶段不给 |
| `POST /courses` `{code, name}` | `code` 必填，最长 20 字；`name` 最长 80 字。回 `course`，带一个配色 |
| `POST /lectures` `{courseId, title, language, source}` | 检查课程、语言、来源。`record`、`tab` 先查当天现场录音分钟数，超了回 429 加说明；本阶段还不收分段，所以再回 501“录音功能还没开放，请上传录音”（不让前端开始录一堂存不下来的课）。**第二阶段**：`record`、`tab` 照常建课（`LIVE_RECORDING=off` 时仍回 501），分钟数也算上正在录的课。`link` 回 501。`upload` 建课，状态 `recording`（和示例数据一致），回 `lecture` |
| `POST /lectures/:id/recording` | 只在 `recording` 状态收。流式收完用 `ffprobe` 确认有音轨，没有就删掉并回 415。存成固定的文件名 `recording`（不带扩展名），这样 ffmpeg 按内容识别格式，上传的文件名改不了它的读法（比如把文件叫成 `.m3u8` 当播放列表读）。同一堂课再传一次会覆盖。**第二阶段**：现场录音的课回 409 |
| `POST /lectures/:id/slides` | 在 `recording` 或 `failed` 状态收（失败后补上课件再重试）。检查 `%PDF` 文件头，不是 PDF 回 415。笔记已生成后再传（补传课件）本阶段回 409 加说明；这个检查放在文件收完之后，免得浏览器还在发送时就收到回复，把它当成网络错误 |
| `POST /lectures/:id/finish` `{duration}` | 幂等：已经是 `processing` 或 `ready` 就原样回状态，不重复排队。没收到录音回 409“这堂课没有收到录音”。否则设 `processing` 并排队。**第二阶段**：现场录音的课要收到过第一段，见下 |
| `GET /lectures/:id/status` | `{status}` |
| `POST /lectures/:id/retry` | 只在 `failed` 时排队重跑，其他状态原样回。已转写过的不再转写，只重跑写笔记 |
| `GET /lectures/:id` | `{lecture, detail}`，笔记没好时 `detail: null`。**第二阶段**：`detail.audio` 是回放链接 |
| `DELETE /lectures/:id` | 删记录、文件、笔记、成本以外的一切；正在跑的流程会被中止，跑完的结果丢掉。上传进行中被删，收完的文件也会被丢掉。成本日志保留（课堂 id 留着，用来算账） |

`lecture.duration` 用转码后音频的实际长度（`ffprobe`），不用前端传的计时。`lecture.date` 是显示用的文字：当天是 `Today`（中文界面会翻译），否则如 `Tue 10 Nov`。

## 处理流程

在服务进程里跑一个队列（并发数 `PIPELINE_CONCURRENCY`，默认 2）。服务重启时，状态还是 `processing` 的课会重新排队。每一步的结果都存下来，重试时跳过已完成的步骤：

1. **转码**：`ffmpeg` 把录音（视频则抽音轨）转成单声道 AAC 48 kbps 的 `audio.m4a`，带 faststart，可以拖动进度。这个文件用来转写，也用于回放（第二阶段）。记下时长和文件大小（第 10 节要“转码后的回放文件每小时多大”）。
2. **转写**：`Transcriber.transcribe(audio.m4a, language)` 返回带时间戳的词。原始返回存成 `transcript.raw.json` 方便对比，切好的句子存进数据库。切句：遇到句末标点且这一句超过 3 秒、停顿超过 1.2 秒或一句超过 25 秒就断开；中日韩字符之间不加空格。
3. **课件**：有 `slides.pdf` 就逐页抽文字。读不了（加了密码、文件损坏）就不用课件，照常写笔记，不让整堂课失败。
4. **写笔记**：`NotesWriter.write(...)` 把课程、标题、日期、语言、时长、带秒数的逐字稿、课件文字交给 DeepSeek（JSON 输出模式、流式、开思考），要回 `sections`、`slides`、`alerts`（带 `date`）、`flashcards`、`quiz`。回复逐项读：数字写成字符串、`"true"`、用字母表示的答案都接受；某一项实在用不了（要点没有时间或文字、闪卡没有答案）就只丢这一项。整份回复不是 JSON、或者一个能用的要点都没有，才把错误告诉模型再要一次，最多两次。
5. **整理和校验**：时间夹到 `[0, 时长]` 并取整；`section` 按时间排好、首尾相接、最后一段到时长为止；没有课件时 `slide: null`、`off: false`，`slides: []`；超出页数的 `slide` 改成 `null`；`section.slides` 由要点的页码算出（如 `Slides 3 to 6`）；`alerts.kind` 规范成 `Midterm`、`Deadline`、`Exam hint`、`Quiz`、`Final`；选项数或答案下标不对的测验题丢掉；中文解释转出另一种字体；逐字稿按 `t` 排序。最后用和 `Detail` 类型绑定的 zod schema 校验，不过就是 `failed`。
6. 存 `detail`，带日期的提示存进 `upcoming`，状态改 `ready`。

任何一步出错：状态 `failed`，错误原因记在数据库（不给前端看），日志里打印。

调用转写服务和 DeepSeek 时，只重试对方明确拒绝的（429、5xx）和根本没送到的（连不上）。超时、回复读到一半断掉这类情况不重试：音频可能已经送到并计费，再试一次就付两次钱。

## 成本日志

表 `costs` 每一步一行：课堂 id、步骤（`stt`、`notes`）、服务商、模型、音频秒数、输入 token（命中缓存和未命中分开）、输出 token、其中思考 token、估算美元、时间。单价写在 `.env`，默认值取自各家价目页：Scribe 和 Deepgram 按小时；DeepSeek 按百万 token，并且分高峰（UTC 周一到周五 01:00–04:00、06:00–10:00）和非高峰半价。

`npm run costs` 打印每堂课的成本，以及“每小时录音的转写成本”“按 90 分钟算每堂课的笔记成本”“有课件和没课件的差”“回放文件每小时多大”，对应第 10 节的表。中文解释多出来的成本：`ZH_EXPLANATIONS=off` 跑同一堂课对比。

# 第二阶段：现场录音、Catch me up、回放

日期：2026-11-14。范围：`reference/INTEGRATION.md` 第 2、4、5 节里录音和回放的部分。

## 做到什么程度

**做到**

- `POST /lectures` 的 `record`（麦克风）和 `tab`（网课）可以用了。
- `POST /lectures/:id/chunks`：收分段，按（课堂, `seq`）去重，回实时逐字稿和考试提示；录音中途也执行每日分钟上限。
- `POST /lectures/:id/finish` 支持现场录音，包括“用已保存的部分写笔记”和 `retry`。
- `POST /lectures/:id/catch-up`。
- 回放：`detail.audio.url`（带签名的链接，支持 HTTP Range），以及 4.4 的 `keptUntil` 和 `expired`（`AUDIO_KEEP_DAYS`，默认不用）。
- `npm run costs` 多了实时转写和 Catch me up 两项；`npm run compare-stt -- --chunks 15` 按实时的做法转写，和整段比。

**不做**

- `attachLink`（视频链接）仍回 501。要从各个视频网站把录音下载下来，牵涉版权和网站条款，依赖 yt-dlp 这类经常随网站改版失效的工具，和现场录音也没有共用的部分。等确定要支持哪些网站（学校的 Panopto、YouTube……）再做。（后来做了公开链接，见最后的“视频链接（公开链接）”一节。）
- 分享页的录音（4.3）：分享是第三阶段，默认不带录音。
- 用 WebSocket 流式转写（ElevenLabs 有实时模型）：前端每 15 秒才交一段，用一段一段的普通转写就够，第一句字大约 20 秒出现。

**算失败的情况**：分段重发被存两次或付两次钱；乱序、缺段让整堂课读不出来；网络恢复后补发的一批分段让逐字稿重复；删掉的课还在转写或留下文件；上限到了以后前端卡住、结束不了录音；回放链接不用登录就能被别人猜到。

## 实测：15 秒一段的准确度

没有真实课堂录音（问过用户），用两段 macOS 合成语音测，`npm run compare-stt -- --chunks 15`，ElevenLabs `scribe_v3`：

| 录音 | 整段转写错误率 | 15 秒一轮（实时的做法） | 多送的音频 | 每轮用时 |
|---|---|---|---|---|
| 英文夹粤语，62 秒 | 4.6% | 6.1% | 13% | 1.2 秒 |
| 英文夹普通话，98 秒 | 2.5% | 3.1% | 12% | 1.1 秒 |

多出来的错误不在切口：被切开的词会留到下一轮再转写（见下），逐字对比里没有缺词或断词。差别有两种：短片段里数字写法不同（“第一至”变成“第 1 至”），以及一句粤语被写成了普通话（呢个→这个，唔→不，嘅→的）。15 秒太短，模型判断不准是哪种中文，而粤语夹英文正是主要用户。

**决定：笔记用录音结束后整段重新转写的结果；实时转写只用于录音页（实时逐字稿、考试提示、Catch me up）。**（2026-11-19 改成只转写一次，见文末“现场录只转写一次”。）

- 代价：转写付两次钱。实时 1.12 倍加整段 1 倍，是上传录音的 2.12 倍；按 `scribe_v3` 每小时 0.20 美元算，现场录音每小时转写 0.425 美元。这就是第 10 节要的“实时转写与课后一次性转写的成本差”，端到端实测也是 2.12 倍。
- 好处：上传和现场录音写笔记走同一条路；实时转写有几轮失败（网络、服务商出错）也不影响笔记。
- 合成语音比真实课堂干净。拿到真实录音后请再比一次（`npm run compare-stt -- --language en-yue --chunks 15 录音.m4a`）。如果差别很小，可以改成直接用实时结果写笔记，省一半转写费。

## 分段怎么存、怎么读

用 Chrome 的 `MediaRecorder` 实测（和前端同样的码率和切法）：

- **分段不能单独读。** webm 只有第一段带文件头，后面每段都从一个 cluster 中间开始。Chrome 的 MP4 第一段只有文件头，一点声音都没有，第二段才有声音。
- 每段存成一个文件 `chunks/000123`，数据库 `chunks` 表以（课堂, `seq`）为主键，重发的那段不再存。
- 读的时候用 ffmpeg 的 concat 协议，把第 0 到 k 段当成一个文件，用 `-ss` 跳到要的位置。ffmpeg 跳过前面的部分只读不解码：在一个 90 分钟的 webm 里跳到最后 15 秒只要 0.07 秒，整段解码要 7 秒。跳转位置 webm 精确到采样，MP4 差 10 毫秒以内。文件名用相对路径，所以 4 小时的课命令行也很短（Linux 一个参数最长 128 KB）。
- 到了一半的文件（最后一段停在 cluster 中间）ffmpeg 照样读到能读的地方，不报错。
- 结束时，按 `seq` 顺序拼成 `recording`，转成 `audio.m4a`（和上传一样），然后删掉分段。
  - 缺了中间某段：用 `aresample=async=1` 补成静音，后面的时间不变（webm、MP4 都实测过）。
  - 缺了第一段：读不出来，`finish` 回 409。
- 一堂课的分段总量受 `MAX_UPLOAD_MB` 限制，单段受 `MAX_CHUNK_MB`（默认 10）限制。Chrome 的 MP4 不管码率设置，实测约 105 kbps，所以上限要留宽。

## 实时逐字稿

每收到一段，跑一“轮”：

1. 只看按顺序到齐的分段（缺了第 k 段，就等它到了再往后读）。
2. 从上一轮停下的地方切到已到音频的末尾，送 Scribe。新音频不到 5 秒就等下一段。
3. 结束时间在最后 2 秒之前的词才留下。最后 2 秒下一轮连同新音频再转写一次，被切开的词因此不会写错。下一轮从两个词之间的空隙中间开始。
4. 下一轮开头如果重复了上一轮最后一个词（1 秒以内），就丢掉：端到端实测里，粤语一字一词时，一个字的尾音在下一轮又被听成同一个字。
5. 一轮通常停在一句话中间。最后一个句末标点之后的词先不送，存在数据库里（`live_held`），下一轮接上新词一起送，所以录音页看到的是整句（端到端实测前后对比：之前每两三行就有一句被切成两行）。这半句的字因此晚一轮出现；一句话超过 30 秒还没结束就照送。Catch me up 会带上这半句。
6. 粤语课和整段转写一样转成繁体。存成行，找考试提示，记成本（`costs` 表 stage `live`）。

规则：

- 每堂课同时只跑一轮；跑的时候来的新段，由下一轮一起处理（网络恢复后一下子补发的十几段，不会变成十几轮）。所有课堂同时跑的轮数有上限（`LIVE_CONCURRENCY`，默认 4）。
- 分段的回复最多等这一轮 8 秒（`LIVE_REPLY_WAIT_MS`），等不到就先回空数组，字随下一次回复一起送（INTEGRATION 第 5 节允许）。端到端实测：开始录音后约 20 秒出现第一句（录音页写的是“大约半分钟”）。
- 回复里的行记下是随哪个 `seq` 的回复送出的。同一段重发（上次的回复丢了）时，回复和上次一样，不会漏字，也不会重复。
- 进度全在数据库和分段文件里，服务重启后，下一段来时从上次停下的地方继续。
- 某一轮转写失败：不马上重试，下一段来时连同这段一起转写，没送到的不算钱。服务商长时间不可用、积压超过 120 秒时，只转写最近 30 秒，实时逐字稿跳过中间这段，笔记照样完整。
- 转写服务把每一轮的第一个词当句首大写，接在半句后面时会出现“the Demand curve”。只影响录音页；要改成小写就得猜专有名词（Keynes、November），没有改。
- **实时考试提示用关键词，不用模型**：midterm、final exam、quiz、due next Friday、deadline、期中、期末、測驗、交功課、考試……命中的那一行原样弹出，`kind` 用前端会翻译的五个词，同类提示两分钟内只弹一次。不花钱，没有延迟，弹出的是老师的原话。漏掉或误报只影响录音页，笔记里的提示是课后由模型写的，带日期。
- `LIVE_TRANSCRIPT=off`：不做实时转写，录音页没有字，Catch me up 回 501；每段只量一下长度，用于分钟上限。第 10 节提到可以只在付费版提供实时逐字稿和 Catch me up，这个开关就是为此准备的（按用户区分要等第四阶段）。

## 每日分钟上限

- **开始录音时**（第一阶段已有）现在也算上正在录的课已收到的音频，两台设备不能各开一堂超出上限。`GET /home` 的 `usage.minutesToday` 同样包括正在录的课。
- **录音中途**，难处在前端：它只在开始前检查；分段回复里的错误说明不会显示；除了 404 和 410，分段出错都会留在队列里一直重试。所以：
  - 剩 5 分钟时，这一段回复的 `alerts` 里放一条 `{kind: "Recording", text: "About 4 recording minutes are left today. ..."}`，录音页会像考试提示一样弹出（`Recording` 这个词会被翻译）。
  - 用完的那一段照收，回复里放一条“今天的分钟用完了，已停止保存，结束录音就能用已保存的部分写笔记”。之后的段回 410，前端就不再发这堂课的分段；结束录音时照常调 `finish`，用已保存的部分写笔记。
  - 不能回 429：前端会把这段留在队列里不停重试，结束录音时会卡在“Waiting for a connection”，下次打开页面也补发不出去。
- 分钟数按课堂开始那天算（和第一阶段一样）。

## finish、“用已保存的部分写笔记”、retry

- 现场录音的课 `finish`：至少收到过第一段，否则回 409“没有收到这堂课的音频”。停掉实时转写，设 `processing` 并排队。流程多了第 0 步“拼接分段”，其余和上传一样。仍然幂等。
- 页面被关掉的课一直是 `recording`，分段一直保留（4.2 第 5 条）。学生点“Make notes from what was saved”时，前端先补发本机剩下的分段，再调 `finish`（`duration` 0，不记）。
- `finish` 之后再来的分段：收到过的回 200 空数组（前端把它从本机删掉），新的回 410（不会加进已经在写的笔记）。
- `retry`：拼好的录音已经在就不再拼；失败发生在拼接之前，就从分段再拼。
- 删除正在录的课：停掉这一轮，结果不存，文件删掉；之后的分段回 404。

## Catch me up

- 取最后 5 分钟的实时逐字稿（以已收到音频的末尾为准）。先等一轮把最新的音频转写完（最多 8 秒）。
- 交给 `deepseek-flash`（不开思考，`CATCHUP_MODEL` 可改），要 2 到 4 句英文，只写逐字稿里有的内容。
- 实测一次约 1000 输入 token、不到 100 输出 token，0.0001 到 0.0003 美元（第 10 节“每点一次的成本”）。成本记在 `costs` 表，stage `catchup`。
- 还没有任何字：直接回一句“还没有可以总结的内容”，不调模型。模型出错回 502 加说明，前端会显示。

## 回放

- `detail.audio.url` 是带签名的链接 `/api/lectures/:id/audio?exp=…&sig=…`（HMAC-SHA256，密钥第一次用时生成，存在数据库，重启后链接仍有效），12 小时有效（`AUDIO_LINK_HOURS`）。
  - `<audio>` 发不了 token，所以链接本身就是凭证，别人猜不到。
  - 过期、被改过、换到别的课堂上都回 403。前端播放出错时会重新拿一次课堂（4.2 第 3 条），拿到新链接。
  - 设了 `PUBLIC_URL` 就给完整地址，否则给相对路径（前端和 API 在同一个地址时就是这样）。
- 文件是 `audio.m4a`（AAC 48 kbps 单声道，faststart），支持 Range：206、416、`HEAD`。端到端实测在 Chrome 里能加载，并跳到任意位置。转码后每小时约 21.4 MB。
- 下载：`Content-Disposition: inline`，文件名用课堂标题。
- `detail` 只在 `ready` 时有，所以只有写好笔记的课有回放。

## 录音保留期限（4.4）

- `AUDIO_KEEP_DAYS` 默认 0，表示全部保留，不给 `keptUntil`，和 4.4“现阶段录音全部保留，这些字段都不用给”一致。
- 设成 N 天：
  - `keptUntil` 是上课当天（`APP_TIMEZONE`）加 N 天；
  - `GET /home` 的 `usage.audioDays` 是 N；
  - 启动时和之后每 6 小时，删掉过期的录音（`audio.m4a`、`recording`、分段），`detail.audio` 变成 `{expired: true}`，笔记照常。
  - 只删 `ready` 的课：`failed` 和没录完的课还要靠录音写笔记（4.4）。
- 按会员等级区分天数要等第四阶段。

## 数据库

- 新表：`chunks`（收到的分段）、`live_lines` 和 `live_alerts`（实时逐字稿和提示，记着随哪个 `seq` 送出）、`meta`（回放链接的密钥）。
- `lectures` 加列：`live_from`（下一轮从哪一秒开始）、`live_audio`（已收到的秒数）、`live_held`（还没说完的半句）、`live_limit`（0、1 已提醒、2 已停止）、`chunk_bytes`、`audio_expired`。
- 第一阶段的数据库启动时自动加列，不用迁移脚本。

- 模拟浏览器（ffmpeg 和服务商都是假的）：按顺序；乱序；同一段发两次；缺一段后补上；离线后一下子补发一批；回复超时后字随下一次回复送；某一轮失败；录音中被删；`finish` 没音频、只有后面的段、发两次；`finish` 之后再来的分段；没录完的课用已保存的部分写笔记；缺段的课失败后重试；分钟上限的提醒、停止和 410；不合规矩的分段；`LIVE_TRANSCRIPT=off`；Catch me up。

- 回放：签名、过期、改过的链接、别的课堂、删掉的课、`PUBLIC_URL`、Range 的几种写法、保留期限和清理。
- 端到端（不在 `npm test` 里，花钱）：构建好的前端在 Chrome 里，用假麦克风播录音（Chrome 的 `--use-file-for-fake-audio-capture`），服务在 8788 端口、用单独的数据目录，ElevenLabs 和 DeepSeek 都是真的。三次：

顺手修了第一阶段的两个问题，都在 `src/http/upload.ts`：

- `MAX_UPLOAD_MB` 带小数时（如 0.3），超过上限的文件会被截短，然后当成完整的文件收下（busboy 只在字节数正好等于上限时报超限）。现在上限按整字节算（加了测试）。
- 上传中途被拒（超限、断开）时，临时文件有时删不掉：写文件的流还没打开文件就被停下，删除之后它才把文件建出来，`data/tmp` 里留下一个 `.part`（重启时才清）。已有的上传测试连跑 20 次有 6 次碰到。现在等写文件的流关掉再删，改后连跑 25 次没再出现。

# 第三阶段：学生用已有的课堂

日期：2026-11-14。范围：学生对已有课堂做的事。前端早就在调这些接口（INTEGRATION.md 第 2 节、API-CHANGES.md 第 1、3、4 节），后端之前回 404、409 或空的占位。契约是前端：`src/api/api.ts` 的真实分支、示例分支和 `mockDb`，`src/types.ts`。

## 做到什么程度

**做到**

- 课堂：`PATCH /lectures/:id`（改标题、换课程）；`POST`、`PATCH`、`DELETE /lectures/:id/points`（编辑笔记）；`PUT /lectures/:id/progress`；`POST /lectures/:id/feedback`。
- 分享：`POST`、`DELETE /lectures/:id/share`；公开的 `GET /shared/:id`；`POST /shared/:id/save`（任务里写的 `POST /shared/:id`，前端实际调的是 `/save`）。
- 课程：`PATCH`、`DELETE /courses/:id`；`GET`、`POST /courses/:id/review-pack`。
- `GET /search?q=`。
- 课后补传课件：笔记写好后 `POST /lectures/:id/slides` 也收，把已有的要点放到课件各页下面。
- `npm run feedback` 看学生的反馈；`npm run costs` 多了补传课件和复习包两项。
- `EXAMPLE_SHARE_ID`：公开页面的 “Example notes” 指向一堂分享的课（以前固定隐藏，因为没有分享页）。

**不做**

- 首页的 `week`（本周统计）。进度和测验分数已经存了，但“本周”“已掌握的闪卡”“平均分”的算法是产品决定，前端不给就不显示。
- 分享页带录音：4.3 默认不带，要带是产品和合规上的决定。
- 搜逐字稿和中文解释：API-CHANGES 第 4 节说以后再考虑。
- 会员、付款、正式登录、设置保存：第四阶段。

**算失败的情况**：改了一个要点却存到另一个上；停止分享后旧链接还能打开；分享页露出录音、学习进度或这个学生别的课；删课程留下文件、笔记或能用的分享链接；补传课件改掉了学生的文字、顺序或自己加的要点，或失败后笔记看不到；复习包里的要点不是笔记里的原话、链接不回那一秒；搜到别人的笔记或已经删掉的内容。

## 接口行为

通用规则和前两个阶段一样：出错回 `{message}`；别人的课程、课堂一律 404；“无”的接口回 204。

| 接口 | 行为 |
|---|---|
| `PATCH /lectures/:id` `{title}` / `{course}` | 两种都支持（API-CHANGES 第 1 节），一起给也行。标题 1 到 200 字。`course` 必须是自己的课程，否则 404。id、分享链接、进度、录音都不变；`upcoming` 的课程编号跟着变（`GET /home` 通过课堂查课程编号） |
| `PATCH /lectures/:id/points` `{section, index, text}` | 只改文字；时间、页码、`off`、中文解释都不动（前端改完也是只换文字） |
| `POST /lectures/:id/points` `{section, text}` | 加在这一节最后，回 `{t: null, text, mine: true, off: false, slide: null}` |
| `DELETE /lectures/:id/points` `{section, index}` | 删掉。一节删空了也留着（`points: []`），后面几节的序号不变；前端删完也是这样 |
| 编辑笔记共同的 | 要点按“第几节第几个”定位（INTEGRATION 第 2 节），所以顺序不能变：新加的放在最后，空的节保留。找不到回 404“This note is no longer there. Open the lecture again...”。文字 1 到 2000 字（前端限 600）。笔记没写好回 409；补传课件处理中回 409“Sid is putting the notes under the slides. Try again in a minute.”，这样处理完写回的笔记不会盖掉刚改的 |
| `PUT /lectures/:id/progress` `{known, quizScore}` | 存下来，`GET /lectures/:id` 的 `detail.progress.known` 就是它（去重、排序）。`quizScore` 为 `null`（这次没做完测验）时保留上一次的分数。分数目前只存不用（`week` 没做） |
| `POST /lectures/:id/feedback` `{text}` | 存进 `feedback` 表，1 到 4000 字。跟课堂一起删：删除确认框说笔记会一起删掉，反馈里常引用笔记原文；而且课堂删了，反馈也没法对照着改进 |
| `POST /lectures/:id/share` | 有笔记才能分享，否则 409。分享 id 是 16 位随机字母数字，猜不到。已经分享过的回同一个链接（`lecture.shareUrl` 也是它） |
| `DELETE /lectures/:id/share` | 清掉分享 id，旧链接立刻 404；再分享是新的 id。删课堂、删课程时链接一起失效 |
| `GET /shared/:id`（不用登录） | `{lecture, course, detail, sharedBy}`。`detail` 不带录音（4.3）和分享者的进度。`lecture.id` 给分享 id，不给课堂自己的 id；`status` 给 `ready`（补传课件处理中也照常显示笔记）。`sharedBy` 是分享者的名字，没名字时是 `A classmate`。链接无效回 404“This link is no longer shared.”，不能回 401（前端会让读者去登录） |
| `POST /shared/:id/save` | 要登录（401 时前端登录完会回到分享页）。复制到读者名下：放进编号相同的课程（不分大小写和空格），没有就按分享者的编号和名称新建一门。副本带笔记和带日期的提示（读者的考试雷达会显示），不带录音和进度；分享者自己加的要点在副本里不再标 `mine`；保留上课日期；算上传，不占现场录音分钟。同一份存第二次回第一次的副本；分享者存自己的课回原课堂。副本和原课堂之后互不影响 |
| `PATCH /courses/:id` `{code, name}` | 限制和新建课程一样。允许两门课同编号（新建时也允许），所以不回 409。没给 `name` 就不改 |
| `DELETE /courses/:id` | 课程、里面每堂课（按 `DELETE /lectures/:id` 处理：停掉流程和实时转写、删文件）、笔记、分享链接、进度、反馈、复习包。课程里有一堂现场录音 2 分钟内还收到过分段时回 409（前端本来就会先拦）；页面早就关掉、没录完的课不算 |
| `GET /courses/:id/review-pack` | 见下面“复习包” |
| `POST /courses/:id/review-pack` | 开始做（正在做就不重复），回 `{status}` |
| `GET /search?q=` | 见下面“搜索” |
| `POST /lectures/:id/slides`（笔记写好后） | 见下面“课后补传课件” |
| `GET /lectures/:id` | **第三阶段改了**：有笔记就给 `detail`（以前只在 `ready` 时给），补传课件处理中学生仍能看笔记；带 `detail.progress` |

## 分享链接的地址

链接要指向前端页面（`https://…/#/s/<id>`），而后端不一定知道前端在哪。按顺序取：

1. `WEB_URL`（新设置）；
2. 请求的 `Origin` 头，也就是学生点 Share 时所在页面的地址；
3. `PUBLIC_URL`；
4. 这台服务的地址。

`npm start` 同一个地址提供前端和 API 时，什么都不用设。前端放在某个路径下时 `Origin` 没有路径，要设 `WEB_URL`。链接在分享时存下来，之后 `lecture.shareUrl` 一直是学生复制走的那一个。

## 课后补传课件（API-CHANGES 第 3 节）

**考虑过的做法**：用课件把笔记整份重写一遍，还是只把已有的要点放到各页下？第 3 节要求不能重写：文字、顺序、学生改过的和自己加的都要保持原样。所以模型只回每个要点属于哪一页、`off` 是不是成立，外加每页一个标题；文字一个字都不经过模型。也不把逐字稿发给模型：判断“课件上有没有”只要对照要点和课件文字，省掉大半 token。

- 收文件和以前一样（PDF 文件头、413、上传中途被删）。笔记写好的课：回复之前就把状态设成 `processing`（加一个标记 `refile`），然后排进写笔记的同一个队列。已经有课件的回 409“This lecture already has slides.”。
- 流程（`pipeline.ts` 的 `refile`）：读课件每页文字 → 把讲课的要点（`t` 不为 `null`）从 1 开始连续编号发给模型（用整数编号，不用“2.3”这种会被当成小数的写法）→ 每个要点填 `slide` 和 `off`，模型没提到的要点不给页码、不算 `off`；学生自己加的要点完全不动 → 各节的 `slides`（如 `Slides 3 to 6`）按要点算 → `detail.slides` → 用 `DetailSchema` 校验 → 存回，`ready`。不重新转写，也不重写笔记。
- 回复用不了时，把回复和问题告诉模型再要一次，最多两次（和写笔记一样）。
- 失败（课件读不出、每页都没有文字（扫描件）、模型两次都用不了、服务出错）：不设 `failed`（那样课堂页会显示“笔记未能完成”，原来的笔记反而看不到），改回 `ready`，笔记原样、`slides` 为空，删掉这份 PDF，原因记在 `error`。学生可以再传一次。
- 处理中：`GET /lectures/:id` 照常给原来的笔记；编辑笔记回 409；删除课堂会中止处理，结果丢掉。服务重启后接着处理（`refile` 标记让它只重做这一步，不会重新转写）。
- 成本记在 `costs` 表，stage `slides`。

## 复习包（INTEGRATION 3.3）

**考虑过的做法**

- 让模型重写一份复习讲义，还是只让它挑选和分组？选后者：模型只回“主题名 + 要点编号”，复习表上的每一条都是学生笔记里的原文（包括改过的），出处和时间准确，点了能回到那一秒，不会编出笔记里没有的东西，输出也短。
- “老师提过的”（`hints`）直接汇总每堂课的 `alerts`，不用模型。
- 模拟考试（`exam`）由模型新出 10 到 20 道综合题，每题注明出自第几堂课、第几秒；一道能用的都没有时，退回用各堂课自己的测验题。
- 复习包过时了怎么办：在每个改动课堂的地方（写好笔记、移动、删除、存副本……）去重置复习包，容易漏。改成复习包记住它是用哪几堂课做的；读的时候课程里“有笔记的课堂”变了，就回 `none`。新课写好、课堂移走或移进来、删掉都自动算过时，学生在复习包页再点一次就重做。前端在复习包 `ready` 后不提供“重新做”的按钮，所以过时只能这样表达。API-CHANGES 第 1 节对移动课堂的建议（两门课都改回 `none`）也由此满足。只改笔记文字不算过时。

**行为**

- `POST`：标记 `processing`，在服务进程里开始做（每门课同时只做一个，重复 `POST` 不会重做）。课程里还没有一堂有笔记的课：直接存一个空的复习包（`ready`，三项都是空数组），不调模型，前端显示“Nothing to revise yet”。
- 交给模型：课程编号和名称，各堂课按上课顺序，每堂课的标题、日期、各节的要点（编号、秒数、文字、是否 `off`）和老师提过的考试、截止日期。用写笔记的同一个模型（`deepseek-v4-pro`，开思考）。
- 回复逐项读：编号写成字符串也收；不存在的、重复的要点跳过；没有要点的主题丢掉；选项、答案、出处不对的题丢掉。一个能用的主题都没有，才把问题告诉模型再要一次，最多两次。
- `GET`：没做过是 `none`；在做是 `processing`；做好了、课程的课堂没变是整份复习包，课堂标题按现在的（改过名的显示新名字）；课堂变了是 `none`。
- 失败：下一次 `GET` 回 502“Sid could not make the review pack just now. Try again in a moment.”，之后回 `none`。前端点 “Make review pack” 后一直在轮询这个接口，所以这句话会显示出来，页面回到可以再做一次的状态；只回 `none` 的话学生看不出失败了。
- 服务重启时还在做的复习包会重新做。删除课程会中止它。
- 成本记在 `costs` 表，stage `pack`，`lecture_id` 一栏放课程 id（`npm run costs` 单独汇总）。

## 搜索（API-CHANGES 第 4 节）

- 搜这个学生所有有笔记的课堂的要点：按改过之后的文字，学生自己加的也算（`t: null`），删掉的要点和课堂自然不在。
- `q` 按空白切成词，转小写（前端已经转过），每个词都要出现在要点里，顺序不限，不必相连。最长 200 字。空的回 `{results: []}`。
- 新的课在前，同一堂课按笔记里的顺序，最多 20 条。
- 实现：SQLite 的 `json_each` 从存好的 `detail` 里逐条取出要点，用 JS 比对（SQLite 的 `lower()` 只管 ASCII）。不另建索引表：一个学生几百堂课、几万条要点，一次也就几毫秒，而且编辑、补传课件、存副本都不用多维护一份数据。以后量大了可以换成 FTS5。

## 数据库

- 新表：`progress`（每堂课一行：已掌握的闪卡、最近一次测验分数）、`feedback`、`packs`（每门课一行：状态、做的时候用了哪些课堂、内容）。都跟着课堂或课程级联删除。
- `lectures` 加列：`share_id`（唯一索引）、`share_url`、`refile`、`copied_from`。启动时自动加，不用迁移脚本。

## 做到什么程度

- `PUT /settings`。

## 登录

**考虑过的做法**：

- 邮箱链接（magic link）还是验证码：链接要在同一个浏览器里打开，学生常在手机上收邮件、在电脑上用 Sidenote，码可以抄过去。选码。
- 新邮箱什么时候问邀请码：发码之前问（`POST /session/code` 回“这是新邮箱”），会让别人用这个接口试出谁有账号。改成码对了之后才说是新邮箱（403），只有收得到这封邮件的人知道。码在这时不作废，带上邀请码再发一次。
- 邀请码和账号：一个邀请码一直是一个账号（第一阶段的设计），第一次用邮箱登录时把邮箱绑到这个账号上。新学生用新的码（`npm run invite -- new`），老学生用原来的码，课都在，不用迁移数据。绑过邮箱的码不能再绑别的邮箱。

**安全上的取舍**

- 码 6 位数字，只存 HMAC（密钥是回放链接用的那个），10 分钟有效，错 5 次作废；同一邮箱一分钟一个、一小时 5 个，所有邮箱一小时合计 `LOGIN_CODES_PER_HOUR`（默认 300，保护发信额度和不被拿来骚扰别人）。最坏情况一小时能猜 25 次，命中概率 0.0025%。
- 新码替换旧码。
- 绑邮箱用 `UPDATE ... WHERE email IS NULL`，两个人同时用同一个邀请码，只有一个成功。
- 没设 `RESEND_API_KEY` 时码打印在控制台：能读服务器日志的人就能登录任何人。启动时会警告，只适合在自己电脑上试。
- 邀请码仍然是凭证：没绑过邮箱的邀请码，谁拿到谁就能把自己的邮箱绑上去。和第一到三阶段一样，邀请码要私下给。

**会话**：`sessions.last_used` 一小时最多写一次；`SESSION_DAYS` 天没用的 token 在下一次请求时删掉，回 401，前端去登录页，登录后回到原来的页面。第一到三阶段的 token 从创建时算。

## 方案和额度

`plans.json` 里第一个方案是免费的，其余每个可以有月费（`monthly`，一张卡片，订阅）和/或通行证（`pass`，另一张卡片，一次付清）。两张卡片给的是同一个方案的权限。

学生现在是哪个方案（`billing.ts` 的 `entitlement`）：订阅是 `active` 或 `trialing` → 订阅的方案；否则通行证没到期 → 通行证的方案；否则免费。`past_due`（续费没扣成功，Stripe 还在重试）算免费，因为用户选了到期即降级、不要宽限期；Stripe 重试成功后自动回到 Plus。

**每月**按学生的时区（`APP_TIMEZONE`）的自然月算，1 号重置。比按 30 天滚动好理解，提示里能写“wait until 1 Dec”。

**每月课堂数**：一堂课第一次开始写笔记时记一笔（`quota` 表，删课不删这一笔）；课堂失败时删掉这一笔，重试时再记（2026-11-20 起，和复习包一样：学生没拿到东西）。检查时再加上还在录、还在上传的课。这样：

- 写好笔记再删不能刷额度（钱已经花了）；
- 上传失败或取消删掉的课不算；写笔记失败的课不算；
- 同时开好几堂课也不会超；
- `saveShared` 的副本不算（不花钱）。

**每月复习包**：做好一个有内容的复习包记一笔；检查时再加上正在做的。空复习包不算。失败的不算（虽然花了一点钱，但学生没拿到东西）。

**每天现场录音**：第二阶段的规则不变，上限换成方案的 `dailyLiveMinutes`。

**录音保留**：Free 30 天，Plus 一直保留。用户定了“到期降回 Free，内容全留”，所以付费期间录的课在付费结束后再留 30 天。实现：保留到 `max(上课那天, 方案开启那天, 付费结束那天) + 30 天`。“方案开启那天”是这台服务器第一次以第四阶段启动的时间（`meta.plans_since`），所以上线时不会一下子删掉旧录音，都从上线那天起算 30 天。`AUDIO_KEEP_DAYS` 不再用（启动时提示）。

**原始文件**（第四阶段之后加）：上传的文件、拼好的现场录音都存成 `recording`，只用来转出 `audio.m4a`（48 kbps 单声道 AAC）。回放、下载、重试和保留期限用的都是 `audio.m4a`。实测 5 堂课：`recording` 64.8 MB，`audio.m4a` 35.6 MB，浏览器录音和下载的音频大约 94 kbps，所以原始文件约是 `audio.m4a` 的两倍；上传视频时差得更多。决定：

- 笔记写好（`saveNotes` 之后）就删 `recording`，前提是 `audio.m4a` 在。删不掉只记一条警告，不影响笔记。
- 失败的课不删：重试可能要重新转码。
- `sweepOriginals`（`audio.ts`）在启动时和每六小时删一次：以前写好的课，以及当时没删掉的。只删状态是 `ready`、而且 `audio.m4a` 在的课。
- 代价：以后想换更高的码率重新转码，或者转码出了问题想用原文件重做，都做不到了。
- `lectures.recording_file` 不清空：写好笔记的课不会再走转码这一步（重试只对失败的课，补传课件只重做课件那一步）。
- 测试（`pipeline.test.ts`）：写好后删、`audio.m4a` 照常播放；失败的课保留、重试后再删；启动清理只删该删的（没有 `audio.m4a`、失败、还没交的课都保留）。`live.test.ts` 和 `live-media.test.ts` 原来在写好笔记后读 `recording` 检查拼接结果，现在改成检查交给转码的内容。

## 付款（Stripe）

不用 Stripe 的 SDK，直接调 HTTP 接口（五个：建、查、关 Checkout，查订阅，建账单页面），少一个依赖，测试也简单。价格用 `price_data` 现场给，不用在 Stripe 后台建商品和价格；以后改价只改 `plans.json`，已订阅的人继续按原价续费。

支付方式不在请求里写死（`payment_method_types`），用 Stripe 后台开了的那些；Stripe 在订阅里只给能续费的。所以要在后台打开支付宝和微信支付，学期通行证才有这两个选项。

**Stripe 告诉我们的事**：

- webhook `POST /api/stripe/webhook`，按 Stripe 的规则验签名（HMAC-SHA256，5 分钟内）。用到 `checkout.session.completed`、`checkout.session.async_payment_succeeded`、`checkout.session.async_payment_failed`、`checkout.session.expired`、`customer.subscription.created`、`customer.subscription.updated`、`customer.subscription.deleted`。
- 订阅的事件来了不信事件里的那份，再去 Stripe 查一次最新的（事件可能乱序）。
- 学生开一个新的 Checkout 之前，先在 Stripe 关掉他还开着的旧 Checkout（另一个标签页、点了两次），只有最新的选择能付款，不会有两个按月订阅同时续费。关不掉说明已经付了：先把它算上，再按规则判断这次选择。万一还是有了两个付费订阅，日志里会写明，要在 Stripe 后台取消一个并退款。
- 每个 Checkout 只处理一次：`checkouts` 表的状态从 `open` 改成别的，和延长通行证在同一个事务里。同一个事件来两次、webhook 和“回来时去问”同时到，都只算一次。
- **不只靠 webhook**：学生付完回到设置页，`GET /home`、`GET /plans` 会去问 Stripe 这个学生最近一天还开着的 Checkout；订阅的付费期过了还没收到续费的消息，也去问一次（10 分钟最多一次）。所以在自己电脑上没配 webhook 也能完成第一次付款；续费和取消还是要 webhook。Stripe 连不上时照数据库里的显示，不报错。
- Stripe 的 API 版本 2025-03-31 把订阅的 `current_period_end` 挪到了 `items` 里，两处都读。“用到期末再取消”有的版本是 `cancel_at_period_end`，有的是 `cancel_at`，两个都认。

**安全**：`sk_live_` 和 `rk_live_` 开头的 key 要设 `STRIPE_ALLOW_LIVE=on` 才用，否则付款关掉并在启动时说明。测试里 Stripe 全部用假的（`StubPayments`），真实请求的格式用本地假服务器检查（`test/payments.test.ts`）。

**选卡片时**（`POST /checkout`）：选现在的方案 409；订阅中选 Free → 账单页面（在那里取消，用到期末）；续费失败（`past_due`、`unpaid`）选付费方案 → 账单页面换卡；通行证期间选 Free 或月费 409（通行证不续费，到期自动回 Free；月费等通行证用完再买，免得重复付钱）；订阅中选通行证 409。

# 视频链接（公开链接）

日期：2026-11-16。范围：`POST /lectures`（`source: "link"`）、`POST /lectures/:id/link`，以及它们之后的 `finish`、`retry`、状态和失败原因。之前 `source: "link"` 回 501。契约是前端：`src/api/api.ts` 的 `attachLink`、`src/pages/NewLecture.tsx`（新建、发链接、`finishLecture`、等笔记），新的 `halfnote.html` 也是同一个流程。

## 为什么、做到什么程度

有网上回放的课，学生现在要先把视频下载下来再上传。贴一个链接就能出笔记，少一步。

**做到**：yt-dlp 打得开的公开链接：YouTube、Google Drive 公开文件、Vimeo、Dropbox、不设密码的 Zoom 分享录像、公开的 Panopto，以及直接指向音视频文件（.mp4、.mp3、.m3u8……）的地址。下载在后台做，之后转码、转写、写笔记和上传完全一样。

**不做**：要登录才能看的链接（学校账号下的 Panopto、Canvas、Moodle、学校的 Zoom）：服务器没有学生的登录状态，失败原因里请学生改用“录网上课堂”或下载后上传。不带 cookies 去下载。不收直播。

**算失败的情况**：学生能借这个接口让服务器访问内网或本机的地址；下载卡住不结束，或删掉课堂后还在下载；超过上传上限的文件被整个下载下来；失败了学生只看到“请重试”，却不知道重试没用；YouTube 挡住下载时课堂一直停在 processing。

## 用户定的

| 问题 | 决定 |
|---|---|
| 用什么下载 | yt-dlp（需要定期更新：网站改版后旧版本会失效） |

## 考虑过的做法

- **只收直接的音视频文件链接**，ffmpeg 直接读，不加依赖。学生很少拿到这种链接，几乎没人用得上。
- **在 `POST /lectures/:id/link` 的请求里下载**：一堂课的视频下载要几十秒到几分钟，会和 4.5 MB 上传那次一样被代理超时断开。改成请求只存链接，下载放进处理流程的第 0 步。
- **只检查学生给的网址是不是内网地址**：挡不住跳转（公网网址 302 到 `169.254.169.254`）和 yt-dlp 自己再去请求的地址（播放列表里的分片、页面里找到的视频地址）。改成 yt-dlp 的所有流量都走本进程里的一个小代理，代理只连公网地址。

## 接口行为（我定的）

- `POST /lectures`，`source: "link"`：和上传一样算每月课堂数，不算每天现场录音分钟。机器上没有 yt-dlp（启动时检查）时仍回 501，文案不变。
- `POST /lectures/:id/link`，body `{ url }`：只收 `source: "link"`、状态 `recording` 的课；`url` 要是 `http`/`https`、最长 2000 字，主机不能是 IP 写法的内网或本机地址、`localhost`，否则 400。存进 `lectures.link`，回 204。再发一次覆盖。
- `finish`：链接课要先有链接，否则 409。之后和上传一样进 `processing`、排队。
- `retry`：失败的链接课可以重试。下载已经成功过（有 `recording`）就从转码开始，否则重新下载。
- `GET /home`、`GET /lectures/:id`：`lecture.link` 是学生贴的链接（前端显示“打开原视频”）。失败的课多一个 `lecture.error`：给学生看的一句话，只在知道原因时给（目前只有下载失败），其余失败不给，前端照旧显示通用的文字。

## 处理流程：第 0 步，下载

链接课没有 `recording` 时先下载：

```
yt-dlp --ignore-config --no-playlist --playlist-items 1
       -f "bestaudio[只走 http 的协议]/best[同上]" -S res:480   # 没有单独音轨时不高于 480p
       --match-filter "!is_live & duration <? 18000"           # 5 小时以内；不知道长度的放行
       --max-filesize <MAX_UPLOAD_MB 换成字节>
       --downloader native --ffmpeg-location <不存在的路径> --fixup never
       --proxy http://127.0.0.1:<代理端口>
       -o <临时目录>/media.%(ext)s -- <链接>
```

（实现后按审查补的）

- **不用 ffmpeg**：yt-dlp 会把带不支持特性的播放列表（比如 `SAMPLE-AES` 加密）交给 ffmpeg。ffmpeg 不走 `--proxy`，只认环境变量（还认 `no_proxy`），而且杀掉 yt-dlp 时它不会停。所以给一个不存在的 ffmpeg 路径，这类链接直接失败；格式也只选 yt-dlp 自己用 HTTP(S) 下载的（rtmp、rtsp 会启动别的程序）；子进程的环境里去掉所有代理变量。
- **进程组**：yt-dlp 在自己的进程组里跑，停的时候整组杀掉，并在 `exit` 时就结束，不等它留下的进程关掉输出。
- **两条队列**：要下载的链接课先进下载队列（`LINK_CONCURRENCY`，默认 2），下载完再进写笔记的队列（`PIPELINE_CONCURRENCY`）。慢的下载最多占 30 分钟，但不会挡住别的课。
- **代理按顺序试每个地址**：主机名解析出几个地址（都检查过）时，第一个连不上就试下一个，比如没有 IPv6 的服务器遇到先列 IPv6 的网站。
- **分享页不带链接**：`GET /shared/:id` 不给 `lecture.link`（分享页本来就不放录音），同学存下的副本也没有链接。
- **前端**：发链接被拒（400）时，前端删掉刚建的课，不留下占每月额度的空课。

- 删课或停服务时中止（`AbortSignal`），超过 `LINK_DOWNLOAD_MINUTES`（默认 30）也中止。
- 下载完用 ffprobe 确认有音轨，存成 `recording`（和上传一样不带扩展名），然后照上传的流程走。
- 下载失败时课堂标为 `failed`，`error` 记 yt-dlp 的原文（看日志用），`lecture.error` 给学生的一句话按 yt-dlp 的输出归类：要登录或私密、YouTube 当成机器人、太长或太大、直播、链接里找不到视频、其他。

## 代理

本进程里起一个只监听 `127.0.0.1` 的 HTTP 代理（支持 `CONNECT` 和普通 HTTP），只给 yt-dlp 用。每个连接：解析主机名一次，任何一个地址是内网、本机、链路本地、运营商 NAT、组播、保留地址（IPv4 和 IPv6，含 IPv4 映射的 IPv6）就拒绝；否则连到刚解析出的那个地址（不再解析一次，防 DNS 重绑定）。只放行 80 和 443 端口。

## 前端

React 前端（本仓库）：失败的课堂页有 `lecture.error` 时显示它，代替“Your recording is safe”那句。`halfnote.html` 的改法写进 API-CHANGES.md 给前端。

|---|---|---|

# 现场录只转写一次

日期：2026-11-19。之前（第二阶段“实测：15 秒一段的准确度”）现场录音结束后会整段再转写一次给笔记用，转写费是上传录音的 2.12 倍。

## 用户定的

不转两遍。依据：合成语音实测，15 秒一段只比整段多错 0.6（普通话夹英文）到 1.5（粤语夹英文）个百分点，差别是数字写法和个别粤语字写成普通话，到了 DeepSeek 写的笔记里基本看不出；而第二遍转写占现场录总成本约四成。真实课堂录音还没比过，拿到后请再跑一次 `npm run compare-stt -- --language en-yue --chunks 15 录音.m4a`。

## 做法

笔记用实时转写存下的行（`live_lines`），录音结束后只转写实时没转到的部分（`pipeline.ts` 的 `transcribeLive`）：

1. 服务商长时间出错、积压超过 120 秒时，实时那一轮只转最近 30 秒，跳过的那段记在 `lectures.live_gaps`（`[from, to]` 的 JSON 数组），和这一轮的结果在同一个事务里存。录音结束后补转。
2. 最后一轮停下的地方（`live_from`）到录音结尾：平时是最后 2 到 7 秒；中间缺了一段时实时转写会停在那里，后面整段都在这里补；`LIVE_TRANSCRIPT=off` 时 `live_from` 是 0，就是整段转写一次，和上传一样。
3. 最后一轮留着没发的半句（`live_held`）和第 2 步转出来的词接在一起切句，所以最后一句是完整的。

每段从 `audio.m4a` 切出来（`media.cutSpeech`），不到 0.5 秒的不送。每段记一行 `stt` 成本，`meta.recordingSeconds` 是整堂课的长度，`npm run costs` 用它算现场录送出的音频是录音长度的几倍。合并后的行照旧存进 `transcripts`，重试不再转写。

**代价**：笔记里的逐字稿和录音页上看到的一样，准确度是 15 秒一段的水平；实时转写失败的几轮会被下一轮补上，不会缺字。

## 测试

`live.test.ts`：结束后只补转最后一轮之后的 2 秒，笔记和存下的逐字稿就是实时那些行；最后一句被留着时和补转的词接成一整句；服务商出错 150 秒后实时跳过的那段在结束后补上，每段各记一笔成本；`LIVE_TRANSCRIPT=off` 时结束后整段转写一次；从已保存的部分写笔记时也只补转没转到的。
